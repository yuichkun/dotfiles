# 検証の手順 — 「完成」と言う前に通すもの

目視だけの確認は信用しない — 縮小プレビューの目視は崩れを見逃す。機械検査 → 失敗しやすい箇所だけ等倍目視、の順で行う。

検査スクリプトは Phase 0 で作業ディレクトリにコピーした `scripts/` のものを使う（自作・即興は禁止 — 劣化版チェッカーの「問題なし」は検証にならない）。`python3` がシェルのラッパー等で壊れている環境では `/usr/bin/python3` など実体のパスで実行する。

## 1. 参照整合（必須）

```bash
python3 scripts/check_refs.py site
```

HTML の src/href/srcset と、HTML・CSS の url(...) を機械抽出して全数検査する。検出するもの:

- リンク切れ（参照先ファイルが存在しない）
- ルート絶対パス（`/assets/...` 形式）。ローカルの file:// やサブパス配信で壊れるので、相対パスに直す

python3 が無い環境では、同じ検査を自分で行う: 全HTMLとCSSから参照を抽出し、①参照先ファイルの実在 ②`/` 始まりの参照が無いこと、を**全数**確認する。抜き取り確認は不可（一部だけの確認がリンク切れの見逃しを生む）。

問題0件になるまで完了と言わない。

## 2. 固有名詞検査（必須）

```bash
python3 scripts/check_identity.py .
```

`research/identity.json` を基準に、本人向け成果物（site/ probes/ hub/）を走査する:

- `forbidden`（発見済みの誤表記）のヒットは即失敗。表面の修正で済ませず、混入源のファイルまで遡って直す
- 「疑わしい出現」は1件ずつ目視し、誤表記なら identity.json の `forbidden` へ、正当な出現（正しい表記の一部・無関係な語）なら `ignore` へ振り分けて再実行する
- **exit 0 が完了条件**。参照整合・レイアウト・schema の検証が通っても、本人の基本情報が正しいことの検証にはならない

## 3. 素材台帳の突合（必須）

```bash
python3 scripts/check_ledger.py .
```

site/ 内の全画像が台帳（`assets/ledger.json`）に存在し `use: true` であることを機械確認する。台帳に無い画像の混入（帰属未確定の画像）は捏造の入口なので、1件でもあれば失敗。

## 4. レイアウトの機械測定

```bash
python3 scripts/measure_layout.py site
```

site/ 配下の**全HTMLページ**を qa コピーに測定スクリプトを注入して headless Chrome で測る（原本は無変更。スクリプトが site/ に測定残骸を検出した場合も失敗になる）。検出するのは要素のはみ出しと overflow:hidden による文字切れ疑い。

- 報告には測定したページ数を書く（1ページだけ測って全体を語らない）
- 意図した装飾による検出（負マージン等）は、要素名と理由を検証報告に列挙すれば残してよい。**列挙なしの「0件」宣言は不可**
- エージェントのブラウザ機能で同等の測定ができる環境なら、それでもよい（測定ロジックは measure_layout.py 内の INJECT スクリプトを使う）
- Chrome が無い環境では機械測定を諦めてよい。その場合は §5 の目視を「全ページ・等倍・崩れやすい箇所リスト順」に強化し、フィードバックのメタ情報に「レイアウト機械測定: 未実施」と正直に記録する

`[はみ出し]`・`[文字切れ疑い]` が0件（または全件が理由つきの許容列挙）になるまで直す。

## 5. 等倍目視

機械検査が通ったら、壊れやすい箇所だけ等倍（原寸）で目で見る:

- 縦書き・特殊レイアウトの端
- 画像とキャプション（内容と帰属表記が正しいかもここで再確認）
- 一番コンテンツ量が多いページ／一番少ないページ

縮小プレビューでの「だいたい大丈夫そう」は確認したうちに入らない。

## 6. 表示経路の確認

- `python3 -m http.server` でローカル配信して一通り操作する
- 相対パスで作ってあれば file:// 直開きでも開けるはず。両方確認しておくと堅い
