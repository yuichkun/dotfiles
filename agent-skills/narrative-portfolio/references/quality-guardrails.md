# 品質ガードレール — 帰属・事実性・進め方のハードルール

ルールだけ覚えるより、そのルールが防ごうとしている失敗の形を知っている方が正しく応用できる。だから各ルールは失敗パターンとセットで書く。なお過去の制作事例の題材・形式の具体名はこの文書に載せない — 完成形を知ると、新しい対象者への提案がそれに引っ張られる。

## 失敗パターンと対策

| 失敗パターン | どう起きるか | 対策 |
|---|---|---|
| 帰属の推測 | 画像の被写体・文脈を推測でキャプション化する（例: インスタレーション作品の写真に「録音の現場」という創作キャプションを付けて掲載する）。本人からの信頼を大きく損なう | 一次ソースで被写体（何の写真か）が確定した画像だけ使う。出典を画面かキャプションに明示。全素材に「被写体」を台帳として記録 |
| 氏名の捏造 | ローマ字表記から漢字氏名を「自然な変換」で補完し、本人の名前を別人の表記で成果物に載せる。正しい表記は読んだ一次ソースに明記されているのに、統合時に正誤2種類の表記の共存を検出できない。参照整合の検査は通るので「問題0」と誤判定する | canonical identity（一次ソース2件照合・原文コピーのみ）を Phase 0 で確定し、全工程が参照する。統合時に表記揺れを照合し、成果物は固有名詞検査（異表記0件）を通す |
| 実地確認前の断定 | まだ取得していないソースを、確定情報のように一覧で提示する | ソースの列挙は実地確認後のみ。手元のデータを全集合と思い込まない |
| 作り込み先行 | 方向性のすり合わせ前に複数案をフル実装して見せる。本人の判断機会を奪い、時間も無駄にする | 捨てられる粒度で1つずつ出し、反応を待つ。momentum は美徳ではない |
| 検証なき完了報告 | ページ本体の応答だけ確認して「完了」と報告する。実際は参照画像が全滅していても気づかない | 参照の機械抽出 → 全数チェックを完了条件にする |
| 目視検証の過信 | 縮小スクリーンショットの目視で「収まっている」と報告する。縮小プレビューは崩れを隠す | レイアウトは要素座標・scrollWidth の機械測定。目視は失敗箇所の等倍確認に限る |

## 事実性のハードルール

- 出典のない記述は書かない。すべての文・数字・固有名詞は調査書（出典URLつき）に遡れること
- 固有名詞（氏名・組織名・作品名）は一次ソースの原文からコピーしたものだけ書く。ローマ字・かな・記憶からの変換・補完は捏造として扱う
- 不明なことは「不明」と書く。取得できなかったソースは「取得できなかった」と調査書に記録する（それも事実性の一部）
- 脚色を使う場合（映画予告調など）は、脚色であることが演出として本人と合意されている場合に限る。事実の水増しには使わない
- 数字は実測のみ。「約」「多数」でごまかさず、数えた方法とセットで書く

## 帰属のハードルール

- 画像は「何の写真か（被写体）」が一次ソースの構造から確定したものだけ使う。ファイル名・雰囲気・文脈からの推測は禁止
- 確定の手段の例: サイトの構造化データ（タイトルとサムネイルの対応）、記事のHTML構造（本文中の写真と関連記事サムネの区別）、著者クレジットの明記
- 使用画像は出典を画面内かキャプションに明示する
- 台帳は `assets/ledger.json`。列は「ファイル・出典URL・被写体・確定手段・帰属・使用可否」（**この定義が唯一の正**）。使う前に必ず引き、Phase 6 で site/ と機械突合する（check_ledger.py）
- 第三者の権利物を含む素材は、成果物をローカル閲覧に留める前提で扱う。公開するなら権利物を除くことを本人に明示する

## 進め方のハードルール

- 質問には、まず答える。本人から質問が来たターンは会話として完結させ、返答と同時に作業ツールを回さない
- チェックポイント（方向選択・決定書・初稿トーン）では本人の反応を待つ。無言で先に進まない
- トークンを大きく消費する処理は、対象一覧・規模・概算を見せて明示のGOをもらってから
- 本人に判断を求めるときは、前提をゼロから共有する。作業中の中間状態を本人が知っている前提で聞かない
- 長い説明や選択肢の比較は md ファイルに書いて渡し、会話には要点だけ出す
- フィードバックの回答支援では、本人の発言にない理由・評価・具体化を本人の回答として確定しない。AIが下書きした文面は本人の確認を取ってから採用し、本人が「支援不要」と指定した設問は回答を原文のまま記録する
