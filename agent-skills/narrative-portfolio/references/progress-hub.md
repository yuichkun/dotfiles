# 進行ハブ — 本人向け提示の統一Web UI

フェーズごとに提示方法を即興すると、走行によって出力がばらつく（あるときは画像付きHTML、あるときは会話内の長いテキスト、あるときは内部ファイルパスの列挙）。本人向けの閲覧・比較・現在地の把握は、**スキルに同梱されたテンプレート**で作る進行ハブに統一する。実行エージェントが書くのはデータファイル（`hub-data.js`）だけ。見た目と構造はテンプレートが固定する。

## セットアップ（Phase 0 で1回）

1. スキルディレクトリの `assets/hub/` 一式を作業ディレクトリへコピーして `hub/` にする
2. `hub-data.example.js` を `hub-data.js` という名前で複製し、値を実データに置き換える
3. `hub/index.html` を開いて表示を確認する

```
hub/
  index.html          進行ハブ（本人は常にここから入る）
  coverage.html       coverage report 画面（Phase 1）
  scoring-board.html  採点ボード（Phase 1）
  hub.css             共通スタイル
  hub-data.js         表示データ（エージェントが更新するのはこのファイルだけ）
  hub-data.example.js 記入例（架空データ・コメント付き）
```

## 鉄則: テンプレートを編集しない

- `index.html` / `coverage.html` / `scoring-board.html` / `hub.css` は**編集禁止**。走行ごとに見た目や構造が変わると、試行間の比較（この実験の目的）が壊れる
- 更新するのは `hub-data.js` の値だけ。キーの追加・削除・構造変更も禁止
- データで表せないものが出てきたら `skill-feedback.md` に記録し、その走行では `findings` や `decision.ask` の文章で伝える。マークアップの即興で解決しない
- 各画面は必須フィールドの不足・件数の不整合を検出すると赤いエラーバナーを出す。**バナーが出ている画面を本人に見せない**

## hub-data.js のスキーマ

記入例と各フィールドの注意書きは `hub-data.example.js` にある。

| キー | 内容 |
|---|---|
| `subject.name` | 本人氏名。`research/identity.json` の canonical 表記をコピー |
| `updatedAt` | 更新日時。ハブを更新するたびに書き換える |
| `phase.current` | 現在フェーズ（0〜7の数値） |
| `phase.checkpoints` | キー `"1" "2" "3"`、値 `"pending"` / `"passed"` |
| `findings` | このフェーズで分かったこと（平易な文の配列。内部ファイルのパスを書かない） |
| `screens` | 今見るべき画面 `{label, href, note}` の配列。Phase 2 の選抜ボード（`../probes/…`）や完成物（`../site/…`）もここから相対リンクする |
| `decision` | `ask`（決めてほしいこと1〜3行）+ `options`（選択肢が明確なときだけ。例: 読みの深さ「ライト/標準/フル」） |
| `next` | 決定後に何が起きるか1行 |
| `coverage` | Phase 1 の読解結果: `total / read / duplicate / irrelevant / inaccessible[{title,url,tried}] / digest[]`。ステータス合計が `total` と一致しないと画面がエラーを出す |
| `tiers` | `S/A/B/C` 各配列 `{title, summary, reason, url, img}`。S/A は**全件**。`img` はサムネイル・OGPのURL、無ければ `null`（プレースホルダ表示） |

## 更新のタイミング

フェーズの節目（報告・GO確認・チェックポイント）ごとに `hub-data.js` を更新し、`hub/index.html` を開き直す。TUIへの通知は1〜3行: 何が更新されたか+何を決めてほしいか。決定・回答・質問は会話で受ける（ハブは表示専用。画面の固定文言でもそう案内している）。

## 採点ボードの完了条件（Phase 1）

「本人が昇格・降格を判断できる状態」で見せる:

- S級・A級は全件が `tiers` に入っている。S級だけ見せて「Aから上げたいものがあれば言って」と聞くのは不可（比較対象が見えていない）
- 各項目に採点根拠（`reason`）と出典URL（`url`）
- `img` は source card の `visual` に記録したサムネイル・OGP。キャプションはタイトルのみで、被写体を推測した説明を付けない（帰属ハードルールと同根）

## フォールバック（ブラウザで開けない環境）

Phase 0 の能力チェックでブラウザ手段が無い場合は、ハブと同じ構成（現在地・分かったこと・決めてほしいこと）を md か会話で提示する。例（Phase 1 の coverage report）:

> 全64件の読解が終わった。読めたのが59件、読めなかったのが3件（旧個人サイトなど — アーカイブまで試してダメだった）、重複が2件。
> 分かった骨子: 障害対応の連載が反響・内容ともに突出していて、リポジトリ群も「予防を仕組みにする」方向で一貫している。
> 次は重要度（S/A/B/C）を付けて見せる。進めていい？

この場合も内部ファイルのパス列挙を報告の主役にしない。
